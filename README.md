# pi-app

A mobile-first web UI for the [pi](https://pi.dev) coding agent.

A single **Node** process hosts every chat session in-memory using pi's SDK
(`@earendil-works/pi-coding-agent`, `AgentSession`), serves the React frontend,
and bridges browsers to their sessions over WebSocket. One process serves many
sessions — sessions are just async orchestrators of cloud LLM calls, so the box
only needs to juggle I/O, not a process per chat.

## Architecture

```
browser ──WS /ws?session=<id>──► Node server ──► AgentSession (in-memory, pi SDK)
                                   │  Manager: Map<id, AgentSession>
                                   │  fan-out events, reattach by id, idle reaper
                                   └── serves the built React app + /api/*
```

- **One AgentSession per session id**, kept in memory. Reconnecting with the
  same id re-attaches to the running session (no new process, no leak).
- The browser owns a stable session id (persisted per-tab), so reloads and
  flaky networks re-attach instead of spawning new sessions.
- A WebSocket can detach (tab close) without stopping the session; an idle
  reaper disposes detached, idle sessions after a TTL.

## Layout

```
web/        React + Vite + TypeScript frontend (source)
  src/api/      typed pi RPC protocol + WebSocket client
  src/hooks/    useSession state machine
  src/components/  Header, Transcript, Composer, sheets
server/     Node + TypeScript backend (the deployable unit)
  src/index.ts    HTTP (static + /api) + WebSocket
  src/manager.ts  session pool: create/attach/detach/reap, event fan-out
  src/rpc.ts      pi-RPC command → SDK call translation
  src/config.ts   config-dir provisioning (clone/seed repo, auth, packages)
  src/sessions.ts /api/sessions listing
  public/         built frontend (generated by `web` build; gitignored)
Dockerfile  build web → build server → node runtime
```

The frontend builds into `server/public`, so `server/` is self-contained.

## Run locally

```bash
make dev     # Node backend :8080 + Vite dev server :5173 → http://localhost:5173
```

Uses your `~/.pi/agent` config and credentials. Backend only (serves the built
frontend): `make dev-server`.

Production build:

```bash
make build   # web → server/public, then tsc → server/dist
cd server && node dist/index.js
```

## Configuration (env)

| env | default | purpose |
|-----|---------|---------|
| `PORT` | `8080` | listen port |
| `PI_CWD` | `cwd` | agent working dir + session-storage slug |
| `PI_CONFIG_REPO` | — | git repo holding the `.pi` config (production) |
| `PI_CONFIG_SEED` | — | source dir to seed portable config from (local dev) |
| `PI_CONFIG_DIR` | `/data/pi-config` | the container's own config dir |
| `PI_CONFIG_SUBDIR` | — | subdir holding the agent config (e.g. `agent`) |
| `PI_AUTH_FILE` | — | `auth.json` to overlay into the config dir |
| `GITHUB_TOKEN` | from `pi-app.env` | HTTPS clone of private `PI_CONFIG_REPO` |
| `PI_BIN` | bundled SDK `pi` | pi binary used for `pi install` |
| `PI_MAX_SESSIONS` | `100` | safety cap on concurrent live sessions |
| `PI_IDLE_TTL_MS` | `1800000` | dispose detached + idle sessions after this |

### Config resolution

The container owns its config dir. Portable text (settings, memory, prompts) is
cloned from `PI_CONFIG_REPO` (or seeded from `PI_CONFIG_SEED`); platform-specific
packages declared in `settings.json` are (re)installed in-container via
`pi install` in the background after startup. `auth.json` is overlaid from
`PI_AUTH_FILE` and is never committed to the config repo.

## Docker

```bash
make dev-docker   # build + run, seeding config from ~/.pi/agent → http://localhost:8080
```

## Deploy

Push to `main` → GitHub Actions builds and pushes `ghcr.io/misrab/pi-app:latest`
→ tiberius pulls the new digest and restarts the container. HTTPS (required for
the installable mobile PWA) is provided by tiberius's Caddy reverse proxy at the
app's own hostname (`pi.h.misrab.xyz`) with an auto-renewed Let's Encrypt cert —
one hostname per app, so each installs as its own PWA. Set via `vhost:` in the
tiberius `cluster.yml`.
